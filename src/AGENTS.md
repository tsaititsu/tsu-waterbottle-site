# 前端與 Next.js 開發規範

本規範適用於目前目錄及其子目錄。

## 1. 修改原則

- 先讀現有頁面與元件，再決定修改方式。
- 優先沿用既有元件，不建立功能重複的新元件。
- 不因為修改一個畫面而重新設計整個網站。
- 不擅自更換主色、字體、間距系統或 UI 套件。
- 不修改無關頁面。

## 2. Server 與 Client

- 預設使用 Server Component。
- 只有需要瀏覽器事件、狀態或瀏覽器 API 時才使用 `"use client"`。
- 不可為了方便把整頁改成 Client Component。
- 權限、價格、點數、會員身分與重要資料驗證必須在伺服器端執行。
- 前端隱藏按鈕不能取代真正權限檢查。

## 3. TypeScript

- 禁止使用不必要的 `any`。
- 禁止用 `@ts-ignore` 隱藏問題，除非有明確理由與註解。
- 外部輸入、API 回傳與表單資料必須驗證。
- 共用型別放在既有的型別目錄，不重複宣告相同型別。
- 不隨意使用型別斷言跳過檢查。

## 4. 狀態與資料

每個資料畫面都要考慮：

- Loading
- Empty
- Error
- Success
- Disabled
- 權限不足

不可以：

- 請求失敗後仍顯示成功。
- 無限 Loading。
- 重複送出表單。
- 使用者連點造成重複扣點、重複建立訂單或重複寫入。

## 5. 錯誤處理

- 禁止空的 `catch`。
- 不可忽略 Promise 錯誤。
- 使用者看到的錯誤訊息要能理解。
- Log 不得包含 Token、密碼、完整會員個資或完整命盤資料。
- 錯誤訊息不得揭露資料庫結構或內部金鑰名稱以外的敏感內容。

## 6. 手機版與無障礙

- 以手機版優先檢查。
- 不得產生水平捲動。
- 重要按鈕必須容易點擊。
- 功能不可只靠 Hover 才能使用。
- 表單欄位要有 Label。
- 圖片要有適當 alt。
- 鍵盤應可操作主要功能。
- 不可只用顏色表示成功或錯誤。

## 7. 套件

- 不自行執行 `npm install` 或 `npx` 安裝新工具。
- 若確實需要新套件，先在 PR 說明：
  - 用途
  - 為什麼現有方案不夠
  - 套件維護狀況
  - 安全與體積影響
  - 可替代方案

## 8. 驗收

重大 UI 修改後至少確認：

- 桌面版
- 手機版
- Loading
- Empty
- Error
- 表單成功與失敗
- Console 是否有錯誤
- 原本功能是否仍可使用
