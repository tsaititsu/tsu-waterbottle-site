## SOL 模式與 Codex 任務等級

每份 Codex 任務指令與完成報告，都必須在開頭使用以下固定格式：

```text
SOL 模式：中／高／極高
Codex 任務等級：中／高／極高
```

兩者必須分別判定：

* `SOL 模式`：表示完成任務所需的推理、驗證與審查深度。
* `Codex 任務等級`：表示操作本身可能影響的安全範圍與交付管制強度。

兩者通常相同；若判定不同，必須分別標示，並以較高等級決定停止條件、驗證深度與人工確認要求。

### 中

適用於：

* SEO metadata、JSON-LD、sitemap、robots 與唯讀驗證。
* 一般 UI、文案、測試或低風險功能調整。
* 不涉及登入、權限、會員個資、付款、訂單、資料庫寫入、正式環境或安全規則。
* 修改失敗時可由單一 commit 或檔案回復，影響範圍清楚。

### 高

適用於：

* 登入、權限、管理員、會員個資、資料 ownership。
* 付款流程、訂單、點數、Webhook 周邊程式。
* OpenAI、AI 產生流程、提示詞、AI 結果持久化。
* Supabase 查詢、RLS 周邊程式、非 Production Migration。
* 安全敏感的 Server／Client 邊界或認證守門。
* 需要額外負向測試、權限測試、資料隔離或人工風險審查。

### 極高

適用於：

* Production Database Migration、RLS、Schema 或正式資料操作。
* 付款 Webhook、付款驗證、退款、對帳與正式金流核心。
* 認證核心、管理員權限核心或安全邊界重大變更。
* 正式發布、Production 環境變數或受控 release。
* 全域安全憲法、AGENTS.md、docs 治理與安全規則。
* 大範圍關鍵重構，或錯誤可能造成資料遺失、越權、付款錯誤或正式服務中斷。

### 判定規則

* 任務同時符合多個等級時，選擇最高等級。
* 無法確認時，先提高一級並停止要求確認，不可自行降級。
* 任務進行中若範圍升高，必須先更新兩個標記，再決定是否可以繼續。
* 標記只表示工作模式與管制強度，不代表取得額外權限。
* 標記不得放寬 `.env`、直接 push、PR merge、Production、付款或資料庫等永久禁區。
* `SOL／Codex 等級` 與 `低風險／UI 風險／高風險` 是不同分類：

  * 前者決定任務推理、驗證與操作管制強度。
  * 後者決定 PR 是否可進入 auto-merge、是否需 Preview 或人工審查。
