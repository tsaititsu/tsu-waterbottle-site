# 占卜推演引擎 V2 實作與驗收規格

SOL 模式：高
Codex 任務等級：高

## 任務目標

把已與老師確認的十四主星、正反位、問題方向與十二宮索引邏輯放進正式占卜生成與審稿流程，讓 AI 先回答問題，再從對方、提問者與事情本身推演原因。同時在抽牌與付款前提醒精確時間、多選項與三個月內重複問題，由提問者選擇修改或繼續。

## 不包含的範圍

- 不新增可判斷精確日期或多選項排名的牌卡。
- 不改變 NT$200 的正式付款門檻、退款規則或金流設定。
- 不執行 Production Migration，不新增環境變數，不讀取正式敏感資料。
- 不合併 main，不正式部署；本次先交 Preview 人工驗收。

## 付款前提問檢查

1. 「什麼時候、何時、多久、幾月、哪一天」等精確時間題，在建立占卜紀錄前顯示提醒。已改成單一明確範圍，例如「我在八月底前能找到工作嗎？」，可以直接詢問。
2. 一張牌要比較 A／B、多個日期或多個選項時，提醒每個選項拆成獨立問題、分別抽牌。同一對象的二至三個相關子問題不當成排名題，正式解讀用同一張牌分別推演。
3. 三個月內同一核心問題即使換句話說，仍顯示重複題提醒。問題明確包含新的關鍵事件或進展時，視為新問題。
4. 已登入者只讀取本人近三個月的問題與建立時間；匿名者只使用目前分頁已有的追問前文，不把私密問題長期寫入瀏覽器。
5. 對話框明確說明尚未抽牌、不會收費，並提供「修改問題」與「仍要繼續抽牌」。繼續後正常生成付費答案，不在答案內再次警告；系統只在本次占卜紀錄的 raw payload 記錄已知情原因。

## 底層推演契約

- 先直接回答使用者真正問的結果，再說明理由與可觀察的行動。
- 理由依問題主詞推演對方、提問者、事情本身三層；三種可能可同時成立，讓提問者對照現況。心意題固定先說對方，再說提問者與關係本身。
- 使用者描述的現況與牌義相反時，以牌義為推演主體；可說明目前看到的可能只是表面，但不捏造事實。
- 十二宮只是內部生活方向索引，不加減分、不顯示給使用者。感情統一夫妻方向；受僱工作與薪水用官祿方向；合夥創業同時看合作關係與財務能否成立。
- 五行屬水的星曜是天同、天相、太陰、巨門、貪狼、破軍，不稱為「水星」。財星是武曲、天府、太陰。主管與權力角色星曜是紫微、太陽、天府、天相、太陰；七殺不是主管星。
- 廉貞的外靈干擾只能用在整體運勢不順且廉貞反位，並只能說可能性。只有天梁正位可在找工作、感情緣分等題型補充祈求神明可能有幫助；反位回到不要只沿用舊觀念。

## 心意題強制結論

- 十四主星都有獨立正反位契約，同一份資料同時提供第一次生成、第二次審稿與最後程式化結論使用。
- 反位心意題的第一句固定以「沒有心。」開頭，不改成「不是完全沒心」或「其實有心只是退縮」。誤解、情緒、安全感、猜疑、退縮只能當原因，不能推翻結論。
- 老師明確確認的五顆是：天同正位有心但偏舒服陪伴；天相正位目前看不出明確有心；太陰正位有心但藏得深；巨門正位偏向有心但沒說出來；破軍正位偏向有心且想改變關係方向。

## 資料庫與安全影響

- Migration：無。
- Policy／RLS：無。
- 既有資料：不修改。
- 新增的重複題檢查只進行限定 user id 與近三個月的唯讀查詢，只取得 question 與 created_at，不回傳給前端。
- 正式生成仍使用現有 Terra 模型及推理等級設定；本次不讀取或修改 OpenAI Secret，也不在驗收階段發出付費模型請求。

## 測試與驗收

- 單元測試：精確時間、單一日期範圍、多選項、多個相關子題、重複題語意、新關鍵變化、十四主星正反位契約。
- 整合測試：建立 API 先回提醒、確認後才建立紀錄、追問前文、已登入本人歷史查詢、正式生成與審稿共用推演契約。
- 穩定性：typecheck、lint、專案完整測試與 build。
- 人工 Preview：手動與自動抽牌、修改與繼續按鈕、Esc 鍵、焦點循環、手機版對話框、已登入與匿名流程。

## 回復方式

回復本次程式 commit 即可取消付款前提醒與新推演契約；本次沒有 Migration、正式資料變更或環境變數，不需要回復 SQL 或 Secret。
