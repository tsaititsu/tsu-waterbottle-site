# D1 宮位推演模組交接驗證案例 v1

## 文件目的

本文件用幾個互相獨立的脫敏微型案例，驗證：

- 本宮核心與對宮表達不會混成兩顆本宮主星。
- 相反方向必須建立新的本對宮軸結果。
- 生年四化跟著星曜及人物。
- 三方四正與暗合只新增影響，不改寫本宮。
- 飛化依固定順序形成有向因果鏈。
- 不同引擎形成相同行為時，只合併客戶文字，不刪除來源。

這些案例不是同一張真實命盤，也不含生日、姓名、會員或客戶資料。案例中的跨宮關係都視為「可信輸入模組已驗證的 fixture 事實」，只用來測 Contract，不能當成固定星曜排列或命理規則。

## Case A｜本宮天機、對宮巨門

### Fixture

| 項目 | 值 |
|---|---|
| 目標宮 | 命宮 |
| 本宮主星 | 天機 |
| 對宮 | 遷移宮 |
| 對宮主星 | 巨門 |
| 生年四化 | 無 |
| 煞忌 | 無 |
| 其他跨宮資料 | 不提供 |

### 允許來源

**天機本宮核心**

- 聰明。
- 邏輯。
- 研究。
- 規畫。
- 反應。
- 變動。

**巨門表達通道**

- 說話。
- 詢問。
- 說明。
- 討論。

### 預期本對宮主張

```text
天機的聰明、邏輯、研究與規畫
→ 透過巨門的說話、詢問、說明與討論呈現
→ 命主容易一邊說、一邊整理思路，也可能藉由提問及討論釐清事情
```

可建立：

- `life.thinking_behavior`：思考與行為模式。
- `life.capability_tendency`：研究、規畫及說明複雜問題的可能能力傾向。

### 不可出現

- 因為對宮是巨門，就無條件加入爭吵、口舌、不安全感或人際糾紛。
- 把巨門列為命宮的第二顆主星。
- 寫成命主一定口才好、一定從事說話工作或一定會與人爭辯。
- 加入三方、暗合或飛化內容。

### 反向軸檢查

分析遷移宮時，不能重用上述結果：

```text
目標改為遷移宮
→ 巨門成為本宮核心
→ 天機只提供巨門在外如何透過思考、研究、規畫及快速反應呈現
```

即使使用相同兩宮與相同星曜，兩份結果的：

- `targetPalaceId`
- `facetId`
- `actor`
- `targetCoreRefs`
- `oppositeExpressionRefs`

都必須重新建立。兩份結果不能共用同一個 claim。

## Case B｜父母宮紫微化權的 Actor 綁定

### Fixture

| 項目 | 值 |
|---|---|
| 目標宮 | 父母宮 |
| 本宮星曜 | 紫微 |
| 生年四化 | 紫微化權 |
| 主要 Actor | 父親／主要父系長輩 |
| 關係 Actor | 命主對父親、長輩及權威的感受與態度 |

### 預期人物主張

```text
紫微重視面子、尊重與主導
＋ 化權增加掌握、執行、控制與承擔
→ 爸爸或主要長輩可能更重視權威及別人是否尊重他
→ 也可能因較能掌握人事與要求，而讓命主覺得他有能力或控制力較強
```

對應：

- `authority.father_person`
- Actor 是父親或主要父系長輩。

### 預期關係主張

```text
父親人物可能較重視權威及控制
→ 命主在相處中容易注意禮數、階層及對方是否願意聽不同意見
```

對應：

- `authority.relationship_impact`
- Actor 是命主的主觀感受與互動。

### 不可出現

- 把父親的紫微化權直接寫成命主自己有領導力、控制欲或能力。
- 把所有化權一律解成紫微式領導能力。
- 因化權就斷言爸爸事業成功、有職位或一定很會賺錢。
- 把父親人物與命主感受壓成同一項主張。

## Case C｜三方四正與暗合只新增影響

### Fixture

以下關係假設已由可信命盤程式確認：

1. 命宮已有 Case A 的天機本對宮軸結果。
2. 財帛宮是命宮的三方來源，財帛宮有陀羅，且其本宮結果已包含：

```text
陀羅的反覆、拖延及最後容易選錯
→ 財帛宮的理財與用錢分面
→ 面對花錢或投資選擇時可能反覆比較，最後仍容易選到不合適的方向
```

3. 福德宮在此 fixture 的實際地支位置與命宮構成已驗證暗合，福德宮有左輔，且其本宮結果已包含：

```text
左輔的主動幫忙、義氣及互助
→ 福德宮的內在價值與潛意識
→ 命主內心可能把幫助別人、講義氣視為自然選擇
```

### 預期三方影響

```text
財帛宮陀羅造成的金錢選擇反覆
→ 透過已驗證三方關係
→ 明顯干擾命宮天機原本的規畫與人生決定
```

結構欄位：

| 欄位 | 預期 |
|---|---|
| `relationKind` | `TRINE_QUADRANT` |
| `visibility` | `EXPLICIT` |
| `sourcePalaceId` | 財帛宮 |
| `targetPalaceId` | 命宮 |
| `targetFacetId` | `life.thinking_behavior` 或 `life.values_direction` |
| `influenceMode` | `INTERFERE` |

客戶可能表現：

- 命主原本會研究及規畫，但遇到金錢安排時，反覆比較與怕選錯可能讓整體決定拖得更久。

這不是把天機改成陀羅，也不是說命主所有規畫都一定失敗。

### 預期暗合影響

```text
福德宮左輔形成的互助價值
→ 透過已驗證暗合
→ 潛移默化影響命宮做決定時是否願意幫助、支持或顧及別人
```

結構欄位：

| 欄位 | 預期 |
|---|---|
| `relationKind` | `HIDDEN_COMBINATION` |
| `visibility` | `LATENT` |
| `sourcePalaceId` | 福德宮 |
| `targetPalaceId` | 命宮 |
| `influenceMode` | `SUPPORT` 或依實際主張形成其他核准方向 |

客戶可能表現：

- 命主有時在規畫事情時，會不自覺把「能不能幫到別人、是否夠義氣」一起放進考量。
- 主動幫助別人的行為，也可能使別人更願意回過頭幫助命主；這是可能因果，不是固定貴人保證。

### 必須保持不變

Case A 原始天機主張全文與來源保持不變。Case C 只能新增兩條 `ValidatedStructuralInfluence`：

- 一條明顯干擾。
- 一條潛在影響。

兩條不能互相抵銷，也不能合成「整體普通」。

## Case D｜父母宮飛天機忌至財帛宮

### Fixture

| 項目 | 值 |
|---|---|
| 出發宮 | 父母宮 |
| 落入宮 | 財帛宮 |
| 四化 | 忌 |
| 被飛化星曜 | 財帛宮原本存在的天機 |
| Actor 候選 | 爸爸、重要長輩的教育方式，或成長中的家庭金錢經驗 |
| 落入分面 | `money.view`、`money.earning` 或 `money.management` 中受實際證據支持者 |

### 固定推演順序

#### 1. 出發來源

父母宮提供：

- 爸爸。
- 重要長輩。
- 教育方式。
- 成長中的家庭經驗。

本命報告不知道客戶真實背景時，不能硬選唯一來源。

#### 2. 落入面向

財帛宮提供：

- 怎麼看錢。
- 想怎麼賺錢。
- 如何研究與管理金錢。

不在此談存錢；存錢歸田宅宮。

#### 3. 直接宮位因果

```text
父親、重要長輩的教育方式或成長中的金錢經驗
→ 形成命主理解及處理金錢的長期背景
```

直接因果已成立，不需要拉入對宮補因。

#### 4. 化忌動作

```text
空缺、不滿足、放不下、持續在意或反覆想補足
```

#### 5. 天機專屬發生方式

```text
研究方法、比較方向、反覆規畫、尋找更好的做法
```

#### 6. 客戶生活橋接

```text
爸爸、重要長輩的教育方式或家庭金錢經驗
→ 命主容易形成錢不夠、方法還不夠好的感受
→ 持續研究賺錢方向、比較方法及反覆規畫
→ 仍可能找不到真正適合的方向，或因反覆選擇而更加困擾
```

### 不可出現

- 只寫「理財規畫受到影響」。
- 說天機從父母宮飛到財帛宮。
- 斷言一定是爸爸、一定缺錢或一定投資失敗。
- 加入天機核心以外的居家布置、吃喝及生活細節。
- 把存錢困難放入財帛宮。

## Case E｜同一飛化公式換成太陰化忌

### Fixture 差異

Case D 的出發宮、落入宮及化忌動作不變，只把財帛宮被飛化星曜換成太陰。

### 預期不同結果

```text
相同的家庭教育或金錢經驗來源
→ 相同的不足感與持續補足動作
→ 太陰使不足感落在居家環境、布置、吃喝或生活細節的花費與滿足
→ 命主可能在這些地方持續覺得不夠、想再調整或再購買
```

這些例子仍必須符合財帛宮的花錢、用錢或金錢感受，不能變成田宅宮的住家事件。

### 差異保證

| 檢查 | 天機忌 | 太陰忌 |
|---|---|---|
| 出發來源 | 父親／長輩／家庭經驗 | 相同 |
| 落入宮 | 財帛 | 相同 |
| 四化動作 | 空缺、在意、補足 | 相同 |
| 星曜發生方式 | 研究、規畫、反覆找方法 | 居家、吃喝、生活細節與細膩滿足 |
| 客戶可能表現 | 反覆找賺錢或管理方法 | 相關生活花費仍覺得不夠 |

如果兩個 fixture 產生相同生活例子，代表模型忽略被飛化星曜，必須以 `SOURCE_TRACE_INCOMPLETE` 或更精確的固定問題碼拒絕。

## Case F｜跨引擎共同行為不能刪除來源

### Fixture

假設：

1. 本對宮軸結果已支持「命主面對金錢決定時會反覆研究」。
2. 三方影響又使金錢選擇對整體規畫產生干擾。
3. 父母宮飛天機忌至財帛宮也支持反覆研究賺錢或理財方法。

### 內部結果

三項來源全部保留：

- 本對宮原始主張。
- 三方結構影響鏈。
- 飛化影響鏈。

不得因為文字相似就只保留飛化或只保留本宮。

### 客戶寫作

客戶版可以只描述一次：

> 你面對金錢安排時容易反覆研究，希望找到更好的方法；除了自己本來就會多想與多比較，家庭過去教你看待金錢的方式，也可能讓這種不足感更明顯。

內部內容格必須同時引用三項來源，且不得把不存在的家庭經歷寫成已確認事實。

## Case G｜空宮借星的三種程式判定

以下三個 fixture 都由 N0 程式先判定，模型不能自行選擇是否借星。

### G1｜空宮符合資格，借入兩顆主星

Fixture：

| 項目 | 值 |
|---|---|
| 目標宮 | 命宮 |
| 本宮十四主星 | 無 |
| 本宮阻擋星 | 無 |
| 對宮主星 | 天機、太陰 |
| 對宮其他星曜 | 左輔 |
| 生年四化 | 太陰化科 |

N0 必須固定：

- `targetCoreMode="BORROWED_MAIN_STARS"`。
- `borrowedMainStarRefs` 同時包含天機與太陰。
- `borrowedNatalTransformationRefs` 包含太陰化科。
- 左輔不能進入借入清單。

本對宮模組應把天機、太陰及太陰化科當成命宮核心，並以表裡如一推演；不能說這些特質較弱、只藏在內心，或再把同一組星重複算成另一條對宮表現通道。

### G2｜空宮有阻擋星，不得借入對宮主星

Fixture：

| 項目 | 值 |
|---|---|
| 目標宮 | 命宮 |
| 本宮十四主星 | 無 |
| 本宮原有星曜 | 文昌 |
| 對宮主星 | 紫微 |

N0 必須固定：

- `targetCoreMode="NO_MAIN_STAR"`。
- `blockingFactRefs` 只包含本宮文昌。
- `borrowedMainStarRefs` 為空。
- 文昌保留在 `retainedTargetStarRefs`。

本對宮模組只能用命宮合法分面與文昌在地作用建立主張。紫微仍可依正式對宮關係參與必要的表現或影響判斷，但不能進入 `targetCoreRefs`，也不能把命宮寫成紫微坐命。

同樣規則適用於本宮存在擎羊、陀羅、火星、鈴星或文曲任一顆；不需要累積到兩顆才阻擋。

### G3｜空宮只有祿存，仍可借星

Fixture：

| 項目 | 值 |
|---|---|
| 目標宮 | 財帛宮 |
| 本宮十四主星 | 無 |
| 本宮原有星曜 | 祿存 |
| 對宮主星 | 已由 Snapshot 固定的一顆或兩顆十四主星 |

N0 必須固定：

- `targetCoreMode="BORROWED_MAIN_STARS"`。
- 對宮主星進入 `borrowedMainStarRefs`。
- 祿存留在 `retainedTargetStarRefs`，不進入借入清單。

本對宮模組先以借入主星決定財帛宮看錢、賺錢、花錢及管理金錢的方式，再由祿存提供既有助力；只有祿存確實獨坐的情況，也可補充該宮的不安全感。不能因祿存存在就拒絕借星，也不能讓祿存取代借入主星成為整宮核心。

### 空宮案例共同拒絕條件

- 模型自行把 `NO_MAIN_STAR` 改成可借星。
- 借入左輔、文昌、祿存、四煞或其他非十四主星。
- 漏掉實際跟著借入主星的生年四化。
- 把借入主星描述成較弱、隱藏或次要。
- 在 G1 同時把借入主星列為本宮核心及對宮表達，造成重複計算。

## Case H｜父母宮雙主星的三層 Actor

### Fixture

| 項目 | 值 |
|---|---|
| 目標宮 | 父母宮 |
| 本宮雙主星 | 紫微、天府 |
| 關係人物 | 爸爸或主要父系長輩 |
| 命主關係範圍 | 長輩、主管階層、上位者與制度權威 |

同一份命盤事實可以產生三項不同主張，但不能混成一句。

### H1｜關係人物本身

```text
actor = 爸爸／主要父系長輩
doubleStarCoreRef = 紫微天府完整組合
interactionRoleBindings = 無
```

爸爸本身必須用紫微天府完整雙星狀態描述，不能只因紫微是前星，就把爸爸整體縮成紫微。

### H2｜爸爸與命主的具體互動

```text
actor = 爸爸與命主的雙方互動
doubleStarCoreRef = 紫微天府完整組合
interactionRoleBindings.frontStarActor = 爸爸
interactionRoleBindings.rearStarActor = 命主
```

前星紫微可用來理解爸爸在雙方互動中的一側，後星天府可用來理解命主在互動中的一側。這只拆解相處角色，不代表爸爸只有紫微、命主只有天府，也不能刪除 H1 或 H3。

### H3｜命主面對權威的整體態度

```text
actor = 命主
doubleStarCoreRef = 紫微天府完整組合
interactionRoleBindings = 無
```

命主面對長輩、主管階層、上位者或政府制度時，使用完整紫微天府組合分析其態度與處理方式。

主管是權威關係，不因年齡相近或小於命主就改成平輩。政府機關及制度本身不能被人格化成前星紫微；只有出現具體官員或承辦人時，才可另外建立前星對方、後星命主的互動主張。

### 共同拒絕條件

- H1 只用前星描述爸爸整體。
- H3 只用後星描述命主整體態度。
- 把政府制度本身放進 `frontStarActor`。
- 把 H1、H2、H3 合成一項主張，導致 Actor 不可追查。
- 只有角色切分，卻沒有引用合法完整雙星組合。

## 目前結果

- 空宮借星、雙星 Actor、本對宮、三方暗合、獨立飛化及整合的模組責任可以由既有老師決策與正式來源完整描述。
