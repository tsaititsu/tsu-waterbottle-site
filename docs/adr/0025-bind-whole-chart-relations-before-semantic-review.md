# 0025：全盤關係先綁定來源，再進語意審查

全盤整合需要找出整體方向、跨宮重複模式、內在拉扯與深刻感受主題。這些關係不能只靠程式比較 ID 決定，因為兩項不同來源可能描述相同的可觀察行為，也可能只是文字相似、實際機制不同。

另一方面，也不能讓未來模型直接輸出一篇全盤摘要。若沒有程式可驗證的來源邊界，模型可能：

```text
引用不存在的宮位主張
只保留一項來源而漏掉其他證據
把同宮拉扯冒充跨宮關係
把任何煞忌文字都標成深刻感受
以分數或唯一贏家抵銷並存面向
在審查前直接進入客戶寫作
```

因此新增 `d1WholeChartRelationContracts.ts`，把「語意候選」和「來源是否合法」分成兩件事。未來語意階段只能提出四類固定關係，並引用既有未合併來源格；程式負責重建可信來源集合、核對 identity、驗證關係基數及重算 coverage。

固定的 source-bound 規則是：

```text
整體方向：至少一個命宮 Axis 來源
重複模式：至少兩個不同宮位
內在拉扯：至少兩個不同宮位
深刻感受：焦點宮位的相關 N0 scan signal
            ＋含該訊號星曜 placement 的 Palace Axis 證據鏈
```

深刻感受只表示命主可能對該面向較有感，不代表宮位更重要，也不產生事件斷言。後三類沒有合法資料時可以不存在；只有整體方向必須至少一項。

通過 Contract 只代表來源和結構有效，不代表語意已核准。因此結果固定標示：

```text
sourceBindingStatus = validated
semanticReviewStatus = required
customerWritingStatus = blocked
```

原始來源格永久保留，不被關係結果改寫或取代。Contract 不計分、不選主導關係、不保存客戶摘要或 `majorStarsConsidered`，也不包含 OpenAI Runtime、模型政策、重試或報告生成。下一層完成語意審查後，才能建立真正的逐宮寫作內容格來源圖。
