# 0023：逐宮索引全部 Flying Result，不做正負抵銷

48 條 Flying Result 都通過 Fact、Knowledge View 與 Result source
binding 後，仍需要一個程式層把它們交給後續逐宮寫作。這一層若直接產生摘要、計算吉凶總分或只選最強影響，會讓不同來源、不同機制及彼此矛盾的合法可能性消失。

因此新增 `d1FlyingPalaceIntegrationContracts.ts`。它接收完整 48 條已驗證結果，先逐條重新綁回固定 Model Input 與 Knowledge View，再依落入宮建立十二個固定宮位槽位。沒有飛化落入的宮位仍保留空陣列，不能因為沒有內容就從索引消失。

整合層固定禁止：

```text
正負抵銷
吉凶淨分數
選出唯一主導影響
合併成單一結論
產生客戶文章
```

脫敏金標以財帛宮驗證同時落入的八條 Flying Result。父母宮天機化祿可能讓長輩教育或金錢經驗帶來主動找方法、看見機會的傾向；財帛宮天機化忌則可能讓命主反覆研究與比較，卻不容易真正定案。兩者可以同時存在，不能互相取消，也不能由程式判定哪一條才是真的。

這個索引是後續內容格與客戶寫作的完整來源集合，不是報告摘要。未來即使把同一落入宮的多條邏輯結果放進同一次實體 OpenAI 呼叫，也必須回傳逐條結果並通過 48 條完整性驗證；批次方式不能改變本決策。
